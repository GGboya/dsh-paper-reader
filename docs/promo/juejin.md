## 第一篇（主打，最容易爆）：给 AI 回答加上「可点击的原文引文定位」

**标题备选：**
- 我让 AI 读论文的每句话都能三秒核对原文：页码级引用定位的工程实现
- 治 AI 幻觉的土办法：回答必须带页码，页码必须能点回 PDF

**大纲：**
1. 痛点：RAG 答案无法核对 → 用户只能盲信 → 幻觉危害在读论文场景被放大
2. 方案总览：转录时建「页码偏移表」→ 检索命中带页码 → prompt 强制引用格式 → 前端把「第 N 页」渲染成链接 → 跳转 + 片段级高亮
3. 三个技术难点展开：
   - pdf.js 文本提取的坑：连字（ligature）、断词（hyphenation）、页眉页脚污染 → 清洗管线
   - 页码偏移表：转录文本的字符偏移 → PDF 页码的映射怎么建
   - 片段级定位：怎么从引用文本反查到 textLayer 的 DOM 节点并闪烁（`&q=` 引文定位）
4. 效果 GIF + 代码片段
5. 收尾：完整实现在 dsh-paper-reader（MIT）

## 第二篇：零依赖分发——给 npm 插件装一个「自动装 Python 工具链」的能力

**标题：** npm 包要用 Python 工具？我让用户一行命令都不用敲

**大纲：**
1. 问题：babeldoc（PDF 翻译）是 Python 包，插件用户不该为此装 Python
2. 链路设计：uv 独立二进制（GitHub Releases API + sha256 校验）→ uv 托管 Python 3.12 → uv pip install，全部落在用户目录、不碰系统 Python
3. 细节：已有环境的探测与复用、失败降级、平台差异（Windows 为何暂不支持）
4. 通用性：这套「npm 包自带 Python 运行时」模式可复用到任何场景

## 第三篇：Electron 式布局魔术——在不改宿主框架的前提下「偷」一个面板

**标题：** 插件不能改宿主 UI？我用视觉换位把 PDF 阅读器塞进了别人的工作台

**大纲：**
1. 约束：dsh 插件不能 fork 宿主 React 代码，列宽拖拽/折叠必须是原生行为
2. 视觉换位：iframe 承载阅读器 + CSS 布局交换的实现思路
3. 副作用管理：opt-in 开关、localStorage 记忆、退出模式不丢会话
